## Finding 1: CONFIRMED, and sharper than stated

The entry .pyc exemption is incomplete. Reproduced three ways (C1):
1. `python3 -m run_codex_y5 --verify-manifest` on a clean ship fails exit 2 with "unexpected directory in ship dir: __pycache__", because -m writes the self .pyc during get_code before dont_write_bytecode is set, and _verify_manifest refuses any directory not a prefix of a manifest path (run_codex_y5.py:516-540; "__pycache__" is not a prefix). Exactly one self .pyc is left behind.
2. Once that self .pyc exists, the direct form then also fails exit 2 with the same message.
3. Import-then-verify in one process returns (False, 27, ["unexpected directory in ship dir: __pycache__"], "f27c0302...").

The proposed fix (allow top-level "__pycache__" as a directory prefix in _verify_manifest, keeping the file-level rule) was validated on a patched copy: -m clean ship then exits 0 with manifest_ok true, while a forged run_live .pyc is still refused exit 2 with no marker, and a forged nested .pyc is still refused. So the availability half of the proposal works.

But the proposal as stated is INCOMPLETE, proven by four extra cases (C1, labelled F1X):
- Forged self .pyc + -m form: exit 2, but the marker PRINTED. The forged code executed before the refusal.
- Forged self .pyc + plain import: exit 0, marker printed, import succeeds.
- Forged launch_y13 .pyc + plain import: exit 0, marker printed, import succeeds.
- Forged self .pyc + direct form: exit 2, marker NOT printed. The production form is safe (a __main__ script is always loaded from source, never from cache).

Root cause: the scan exempts the two entry .pyc files by path only, so wherever CPython loads an entry module FROM CACHE (-m form, plain import), forged content runs before any in-module check can run. The production form is unaffected, and today the directory rule still makes direct-form verify fail closed on a forged entry .pyc. But if the directory prefix is allowed WITHOUT a content check, a forged entry .pyc would then PASS verification (exempt in the scan and exempt in the file loop) while containing attacker bytecode that executes the moment anyone uses -m or import. The fix must therefore verify entry .pyc CONTENT against a fresh compile of the corresponding source, not just allow the directory. See AMEND A1. Grade: AMEND, not BLOCK, because no production path executes it.
