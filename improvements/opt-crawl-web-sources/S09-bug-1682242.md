# S9. Bugzilla 1682242: tabBrowser is null in WebDriver:NewSession

- Class: (d) Firefox Marionette browserElement is null and session creation failures
- URL: https://bugzilla.mozilla.org/show_bug.cgi?id=1682242
- Accessed: 2026-11-21
- Crawler: OPT-WEB, 2026-11-21 22:50 +07

## What they did

Mozilla fixed NewSession failing when a non-browser window (no tab browser, e.g. Thunderbird or a library/downloads window) is open. Root cause: the initial browser collection assumed every chrome window has a tab browser. Fix: a null check, correctly registering chrome windows without a tab browser.

## Evidence shown

Fixed in Firefox 86, verified in Nightly, covered by automated tests, low risk. The failure signature matches ours structurally: Marionette throws at GeckoDriver newSession when its window enumeration hits a window it cannot handle.

## Applicability verdict: PARTIAL

The upstream fix is already in every modern Firefox, so it does not fix our current Zen failures directly. But it names the mechanism behind our "browserElement is null" on session creation: NewSession enumerates windows and chokes on one that is not a normal browser window. Our mitigation follows: before creating a session, ensure the selected tab is a live browser tab (never a dead or closed tab, never a non-browser window), and if NewSession fails, close or ignore non-browser windows and retry with a fresh live tab focused. This matches our local lesson (open a sacrificial live tab before closing tabs, end the session focused on a live tab).
