# S10. Bugzilla 1682062: browsingContext is null for GetWindowHandles with unloaded tabs

- Class: (d) Firefox Marionette browserElement is null and session creation failures
- URL: https://bugzilla.mozilla.org/show_bug.cgi?id=1682062
- Accessed: 2026-11-21
- Crawler: OPT-WEB, 2026-11-21 22:51 +07

## What they did

Reported GetWindowHandles returning 500 with "browser.browsingContext is null" when unloaded tabs are present, on Wayland (sway), about 10 windows and 140 tabs, geckodriver --connect-existing --marionette-port 2828. Fixed in Firefox 90. Key observation from the reporter: closing the tab selected when geckodriver started leaves the driver unable to find any window until restart; it seems to see only one tab.

## Evidence shown

Full geckodriver trace logs, reproduction across Firefox 83, 84, 85, 86 beta, fixed in 90. The "only sees one tab, and losing the selected tab blinds it until restart" observation is the useful part.

## Applicability verdict: APPLIES

This is the closest upstream analogue to our exact failure: connect-existing on port 2828, many tabs, closing the selected tab blinds the driver until restart. Our local rule (never delete the session while focused on a dead tab, always open a live tab first) is the correct mitigation and is now backed by an upstream report. The fix being in Firefox 90 means Zen, as a Firefox fork, should carry it, so if we still see it, the cause is more likely Zen-specific tab handling or our driver deleting a session on a dead tab, not this bug.
