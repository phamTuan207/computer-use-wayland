## Defect 1 (test-07, FAIL): checker expects "Root: 3 files", fixture computes 5

- Failing check: check.mjs, test-07 branch: `toastText.includes('Root: 3 files, Archive: 3 files, Trash: 0 files, Folder Processed created')`.
- Actual toast (live run): `'Root: 5 files, Archive: 3 files, Trash: 0 files, Folder Processed created'`. All other 7 checks in test-07 pass (names photo-2026-01/05, trash 0, archive "3 files", row4 restored, folder Processed created).
- Root cause: the fixture computes the count from live state (fixtures/test-07-file-manager.html:331-334): `rootVisible` = visible rows in `#table-root-files tbody`. Trace: 8 rows start; move hides img1-3 (5 visible); delete img4 hides it (4); restore unhides it (5 visible: img4, img5, doc1, doc2, doc3). The spec (test-07-file-manager.md step 35) and the checker both assert 3, which matches neither the fixture's count nor any plausible count (8 - 3 moved = 5). The spec/checker author miscounted; the fixture is self-consistent.
- Fix: change the expected string to 'Root: 5 files' in check.mjs (test-07 branch) AND in test-07-file-manager.md step 35. Do NOT change the fixture (it computes from real state).

## Defect 2 (test-09, CRASH): dead id #note-item-archived-draft

- Crash: simulate.mjs test-09 step 6, `page.click('#note-item-archived-draft')` throws `No element found for selector: #note-item-archived-draft` (exit 3). The `--all` run also died here, so tests after 09 never ran in that invocation (per-test runs confirm 10 passes on its own).
- Root cause: fixtures/test-09-notes-sync.html:66 defines the id only in static HTML (`<div class="note-item" id="note-item-archived-draft" data-id="archived">`). The script's `renderList()` runs at load and rebuilds every item as `div.id = 'note-item-' + key` (key 'archived' becomes `note-item-archived`), destroying the static id before any step runs. The id never exists at runtime.
- Three places reference the dead id: spec test-09-notes-sync.md step 29 (click row), simulate.mjs test-09 step 6 (click), check.mjs test-09 branch (`document.querySelector('#note-item-archived-draft')`).
- Second flaw in the same check: `check(!archivedItem, 'Outdated note was not deleted')` is VACUOUS. It passes whenever the element is absent, including when the delete never ran. After the id fix it must assert on `#note-item-archived` absence AND the counter (total 3), not on a never-existing id.
- Fix: rename all three references to `note-item-archived`; make the checker assert `!document.querySelector('#note-item-archived')` plus totalNotes '3'. The delete flow itself is sound (delete removes the key, counter drops 4 to 3); only the id is wrong.
- Note: the other two "missing" ids in test-09 (`note-item-title-shopping`, `note-item-title-conflict`, `note-item-conflict-copy`) DO exist at runtime (built by renderList with ternaries). Verified by reading the fixture, not by grep alone.
