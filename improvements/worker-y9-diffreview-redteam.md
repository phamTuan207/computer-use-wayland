## Attacks attempted and HELD (why each did not break)

### A1. The park: happy path holds, shared tab survives, recheck no longer self-defeats

- `run_agy_y2.py` lines 372-415 (`_park_before_exit`, `__exit__`). The park closes every handle in `opened_tabs` first, clears the list, creates a sacrificial `about:blank` tab via `new_tab` (line 394), removes it from `opened_tabs` (line 399), switches to it (line 402), and only then does base `_cleanup` (`run_live.py` lines 333-349) run DELETE /session with the sacrificial tab current. `opened_tabs` never contains the shared tab in any path I traced: bootstrap removes it (line 2253), `rebootstrap_tab` removes every handle it returns (lines 576, 585 in the 9564304 file), and the main-finally screenshot fallback removes its tab (line 2730). The test session therefore never parks on a keeper tab, and the recheck session (`_recheck_shared_tab`, lines 756-776) now parks on a sacrificial tab instead of deleting the shared tab it just diagnosed, which closes round-2 B2/N8 for the responsive-driver case.
- Walked `_cleanup` order against the park step by step: park loop DELETEs opened tabs, park sets `opened_tabs = []`, park creates the sacrificial tab, base `_cleanup` sees an empty list and goes straight to DELETE /session. No keeper tab is current at DELETE time on this path.
- A handle whose window is already gone: `switch(handle)` raises inside the park loop's try, the except passes, the loop continues to the next handle. A gone window needs no DELETE, and the failure does not abort the park. Held.
- A wedged driver: every `_wd` call has a 30 s urlopen timeout (`run_live.py` lines 367-376), so a hung driver makes the park slow, not wrong. If the driver is hung, DELETE /session times out too and is swallowed by `_cleanup`, so no tab is closed. Held as far as a wedged driver goes; the selective-failure remainder is F1.

### A4. The classification rewrite: the elif chain is complete over the real inputs

- Empty message: no real exception in these paths has an empty `str()`; a bare `RuntimeError()` would diagnose first and land as a live failure only if the body reads VISIBLE with no timeout word, which is the safe default for an unknown error.
- Timeout wording: `wait_for` raises lowercase `timeout waiting for ...` (`run_live.py` lines 491-500), and the exclusion test uses the same lowercase string, so genuine wait_for timeouts stay live failures. A genuine urlopen timeout surfaces as `<urlopen error timed out>`, which contains `timed out` and is caught by the INFRA branch, as the fix comment claims. No capital-T `Timeout waiting for` raiser exists in the runner or the base.
- The two accounting quirks this rewrite introduces are F4, not misclassifications of individual tests.

### A6. The handover fingerprint: sound against ordinary swaps

- `run_agy_y2.py` lines 215-249. The fingerprint is `(asserted_at_unix, st_mtime_ns, st_size)`. Nanosecond mtime defeats a same-second rewrite: any ordinary rewrite updates `st_mtime_ns`, so it is detected even if the content and size are identical. The first check happens in `preflight` (line 2274) before any tab is opened, so there is no driving path with the fingerprint unset; the per-test re-check then compares against it. The only undetected swap is a deliberate `utime` restoration of mtime with identical size and `asserted_at`, which also requires the forger to keep the timestamp field unchanged; that is outside the launcher-trust threat model, and the same forger could edit the runner itself. Cheap hardening is in F6.

## Non-blocking findings (fix with the blocks, or record and move on)

- F1. Park fallback still runs DELETE /session on an uncontrolled current window when the park itself fails. `run_agy_y2.py` lines 372-408: every failure inside `_park_before_exit` is swallowed and returns, and `__exit__` (lines 410-415) then calls base `_cleanup`, whose DELETE /session closes whatever window is current. Concrete selective-failure modes: (a) `new_tab` switch verification fails after POST /window/new succeeded (tab created, handle appended, `switch`/`GET /window` mismatch), leaving the handle in `opened_tabs`; base cleanup then DELETEs it and DELETE /session lands on the adjacent window, which after the park loop deleted the last test tab is a user tab. (b) `goto("about:blank")` inside `new_tab` raises a transport eval error, same outcome. (c) POST /window/new returns an HTTP error while the session is still deletable. A fully wedged driver does not trigger this (DELETE also times out), so the hole needs a fast selective failure, not a hang. Hardening: after a failed park, switch to a known registered tab from `_TEST_TABS` before DELETE, and if no registered tab is switchable, skip DELETE /session entirely and just terminate geckodriver (the session dies with the driver and no tab is closed). Do not rely on the park succeeding.
- F2. The manifest verifier has three small gaps. (a) No pinned file count: `_verify_manifest` (lines 273-296) iterates whatever `files` lists, so deleting an entry (for example the test-07 fixture) silently shrinks coverage; the suite JSON prints `files_checked` but nothing enforces 26. Pin the expected count and the expected file list in the runner. (b) A null md5 plus a missing file passes: if `want` is None and `_md5_of` returns None for a missing file, `got != want` is False (line 295). Reject any entry whose md5 is not a 32-hex string. (c) A malformed entry crashes instead of refusing: `rel` None makes `base_dir / rel` raise TypeError, and a non-dict entry makes `.get` raise AttributeError, both escaping `main()` with no suite JSON (the try in `_verify_manifest` only covers reading and parsing the manifest file, lines 284-287). Wrap the per-entry loop so a malformed manifest returns `(False, ...)` like an unreadable one. Note: editing the manifest to match tampered bytes defeats the check, but that requires write access to the ship dir, where the runner itself lives, so it is outside the stale-copy threat model B3 was written for.
- F3. The server-reuse path verifies one file and trusts the rest. `start_server` (lines 2156-2174) reuses any server on port 8769 that answers 200 for test-01, without checking that its root is the manifest directory. A stray listener rooted at an older ship copy would serve nine stale fixtures plus stale simulate/check while the manifest check on `/tmp/worker-y9-server` passes. The launch procedure starts no such server (the runner starts its own, and flock serializes launches), and every fixture in the repo today matches the manifest, so this cannot corrupt the upcoming run as shipped; it is latent. Hardening: on reuse, probe a second file whose bytes are known (or compare the served root by fetching a marker), and refuse to reuse a server whose root cannot be proven to be the ship dir.
- F4. Fixture-unavailable is counted in the headline `failed` number and exit code, and does not reset the infra streak. `run_agy_y2.py` lines 2654-2664 append to `r.failures`, so the summary has `pass: False`; the suite then reports `"failed": len(results) - total_passed` (line 2804) and exits 1 (lines 2860-2861) even when the only non-pass is a fixture that never rendered a body, which the fix comment says is "not a live test failure". Separately, lines 2750-2753 leave `infra_blocked` unchanged on fixture-unavailable, so INFRA, fixture-unavailable, INFRA aborts as "two consecutive INFRA-blocked tests" although the INFRA tests are not consecutive, contradicting the reset rule recorded in round-2 A3 (reset on non-INFRA failure). The per-test `outcome` field preserves the distinction, so nothing is silently misreported. Hardening: count fixture-unavailable separately from `failed`, and either reset `infra_blocked` on it (strict consecutive rule) or document that the counter is a running infra count, not a consecutive one.
- F5. The `check()` override can turn a passing test into a failure if logging fails. `run_agy_y2.py` lines 460-474: if `log_step` raises (LOG_PATH I/O error, disk full), the exception propagates out of `check()` after `super().check()` already recorded the result, so a test whose checks all passed fails with a runner error, and a failing check gains a second spurious failure plus a diagnose-driven reclassification. Base `check()` never raised. Hardening: wrap the `log_step` call in try/except and print the logging error instead of raising, so the evidence layer can never fail a test.
- F6. The handover fingerprint is not a content hash. `run_agy_y2.py` lines 239-246: a swap that keeps `asserted_at_unix` and size identical and restores `st_mtime_ns` via `utime` passes undetected. This needs deliberate forgery, so it is not a block; adding `hashlib.md5` of the file bytes to the fingerprint tuple would close it for one line.
- F7. Bootstrap ladder time is missing from suite `stall_ms`, and screenshot-fallback tabs leak. The bootstrap runner built at line 2228 accumulates `stall_ms` in the wrapper, but that runner is discarded and only its `hidden_body_encounters` are carried into `boot_info` (lines 2236-2237); a bootstrap that needed ladder recovery therefore reports suite `stall_ms` 0 for that work. Separately, the screenshot-fallback tab created in `main`'s finally (lines 2727-2731) is removed from `opened_tabs` but never registered in `_TEST_TABS` or `bootstrap_tabs`, so the suite-end cleanup (lines 2840-2855) never blanks it; each failed attempt leaves one orphan `about:blank` tab in Zen. Both are cosmetic; register the fallback tab or record bootstrap stall explicitly.
- F8. Small items. (a) `_hyprland_signature` lines 201-208: on a failed `connect`, the socket is never closed (leak of one fd per dead candidate; the success path closes it). Close it in a finally. (b) run_02 lines 1371-1376: `_child_txt` is evaluated twice (once in the condition, once as the detail); a DOM change between the two evals can make the detail disagree with the verdict. Evaluate once into a local. (c) Suite md5 record lines 2829-2832: `__file__.replace("run_agy_y2.py", "run_live.py")` silently returns the runner path unchanged if the file was ever renamed, mislabeling the runner md5 as the run_live md5. Build the path with `Path(__file__).with_name("run_live.py")` as `_verify_manifest` already does. (d) The main-finally screenshot (lines 2726-2741) still captures whatever window is current if `d.handles()` or the fallback `new_tab` raises; the screenshot then contains uncontrolled content and the `wd.__exit__()` park is the only remaining guard. Same narrow class as F1; skip the screenshot entirely when the pre-screenshot switch fails.
