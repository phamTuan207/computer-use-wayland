## BLOCK B1: preflight can never pass on this laptop, Hyprland signature regression

- Evidence: tests/realistic/run_agy_y2.py lines 133-150 define _hyprland_signature() using ONLY the /proc environ source, and it returns None when the variable is absent. The file contains no socket-dir fallback at all (grep for socket.sock returns nothing in the runner). The proven-live code it was copied from, tests/realistic/run_agyq2.py lines 89-141, uses TWO sources: environ first, then the socket directory under $XDG_RUNTIME_DIR/hypr/, with each candidate verified by a real AF_UNIX connect to its .socket.sock. The Y4d docstring there states the reason: "UWSM-launched sessions do NOT carry HYPRLAND_INSTANCE_SIGNATURE in the compositor's own environ, so source 1 is often empty and the dir is the reliable source." Y9's docstring says the opposite: "(robust against stale socket dirs)", so the socket source was deliberately omitted, not accidentally lost.
- Live proof on this exact laptop: improvements/worker-y4d-rerun-log.md, ~18:40 entry: preflight FAILED on the Hyprland signature ("not in the compositor's environ under UWSM") and was fixed by discovering the signature from $XDG_RUNTIME_DIR/hypr/<sig>/ with a socket connect, after which preflight passed and the 10/10 rerun ran. Y9's runner reintroduces the exact pre-fix code Y4d proved fails here.
- Concrete scenario: launch under flock with a valid handover token. BiDi 9222 answers, Marionette 2828 answers, then preflight calls _hyprland_signature(), gets None, and raises at run_agy_y2.py line 2093 ("no Hyprland signature found"), wrapped as PREFLIGHT SAFETY. Exit 2, zero tests run, every launch. The suite is dead on arrival, and the failure looks like a compositor problem instead of a runner regression.
- The v2 plan's claim is false for this function: plan section 3 says the Hyprland SAFETY gate is "(C3-F9, already in base, verified)". The Y9 file does not carry the base's function; it carries a rewritten environ-only version.
- Required fix: restore the Y4d two-source _hyprland_signature() verbatim (environ, then socket-dir candidates sorted newest-first, each verified by AF_UNIX connect), and re-prove it with a laptop-side preflight run before any suite launch. If the laptop-side probe returns a signature from environ alone, withdraw this attack with that evidence; the Y4d log says it will not.

## BLOCK B2: session exit can close a user tab and screenshot user content

- Evidence, mechanism: improvements/worker-y4d-rerun-log.md, finding 1 (lines 89-93): "Shared bootstrap tab does not survive its session: 10/10 tests printed `shared tab gone, rebootstrap` in both runs", with the stated most-likely mechanism "Marionette DELETE /session closes the session's current top-level window." The mechanism is Y4d's hypothesis, but the observation (test tabs die at session exit) is proven 20/20. The runner must therefore assume the worse case: whatever window is current when a session is deleted is the window that dies.
- Evidence, uncontrolled current window, site 1: tests/realistic/run_agy_y2.py lines 2025-2038, bootstrap_tab failure path. On a failed attempt it calls d.close_tab() (line 2032), then the finally block calls wd.__exit__() (line 2038) with no switch in between. After close_tab deletes the current window, the session's current window is implementation-defined and uncontrolled. If it lands on a user tab, DELETE /session closes that user tab.
- Evidence, uncontrolled current window, site 2: tests/realistic/run_agy_y2.py lines 405 and 417, rebootstrap_tab. On a failed new tab it calls d.close_tab() and continues. If all 3 attempts fail, the loop raises after the last close_tab with current uncontrolled. That raise reaches open_fixture (lines 893-899, wrapped as INFRA), then main's finally takes an end-state screenshot of whatever window is current (line 2412) and calls wd.__exit__() (line 2416). Two harms in one path: the screenshot file saved as test evidence can contain the user's tab content, and the session delete can close that tab.
- Evidence, destructive recheck: tests/realistic/run_agy_y2.py lines 552-575, _recheck_shared_tab. It opens a fresh session, switches to the shared tab, diagnoses it, and its __exit__ deletes the session while that tab is current, so the recheck destroys the very tab it diagnosed. After any INFRA, the shared tab is guaranteed dead even if it had recovered on its own, which also defeats the recheck's stated purpose ("it may have cleared on its own").
- Concrete scenario: a persistent hidden body makes all 3 fresh tabs fail in bootstrap attempt 1 (or in open_fixture's final-tab path). Each failure ends with close_tab. The session exit that follows closes the window that is now current. If Zen's active window at that moment is one of the user's tabs, that tab is closed with no record, during a run the owner handed over on the understanding that the user's tabs are never touched. The screenshot at line 2412 may additionally capture that tab's content into /tmp/worker-y9-shots/{test}-a{attempt}.png as supposed test evidence.
- Note the asymmetry that makes this live: in the NORMAL path the current window is always a test tab, so nothing bad happens. The hazard exists only on the failure paths, which are exactly the paths a hidden-body-prone run is most likely to hit.
- Required fix: never let a session exit or a screenshot run on an uncontrolled current window. Before every wd.__exit__() and before the finally screenshot, switch to a known registered test tab (or, if none is alive, create one and switch to it). Apply it at minimum to bootstrap_tab's failure path (lines 2032-2038), to main's finally (lines 2412-2416), and to _recheck_shared_tab (switch to a sacrificial about:blank tab before its session exits, or diagnose without a session delete that targets the shared tab). Re-prove with a laptop-side test that forces the bootstrap-failure path and confirms no non-test tab closes.

## BLOCK B3: no launch-time proof the shipped bytes are the committed bytes

- Evidence: tests/realistic/run_agy_y2.py lines 2479-2482 record md5s for exactly two files (run_live.py, run_agy_y2.py), computed live from the files actually imported. No expected values exist anywhere in the runner, so nothing compares them. No fixture hash is recorded at all, and _read_shipped() (lines 2257-2262) only embeds SHIPPED.md text verbatim, never checks it. SHIPPED.md does not exist yet (no ship has happened, no SHIPPED.md in the repo), so the v2 plan's claim "md5s recorded in SHIPPED.md" and "the run log records the frozen md5s" is currently an unfulfilled promise, and even when the file is written, the runner will not refuse a mismatch.
- Concrete scenario: the ship step copies an older test-07 fixture (or a fixture edited during Y7's fix work) to /tmp/worker-y9-server/agy-y2/fixtures/. The run passes. The suite JSON contains no fixture hashes, so nothing in the run log can tell which fixture bytes ran. The integrity guard does not catch it: the guard only proves the ported verify FAILS on the untouched fixture, and a fixture edited to make a hard step easy (for example a delete handler that auto-restores, or a conflict handler that pre-fills the body) still fails the guard, because most checks fail on untouched. The run would be reported as a clean pass of the committed suite while having run different bytes.
- The same hole covers run_live.py: a stale laptop copy (for example pre-_DIAG_JS-fix) would abort loudly, but a subtly different copy (different classify thresholds, different settle sleeps) would run silently and report only its own hashes.
- Required fix: bake a manifest of expected md5s for EVERY shipped file (run_agy_y2.py, run_live.py, all 10 fixtures, all 10 specs, simulate.mjs, check.mjs) into the runner or into a manifest file the runner reads at launch, verify every file before preflight, and refuse to run on any mismatch. Record the manifest in the repo and generate SHIPPED.md from it at ship time, not by hand.

## Non-blocking findings (fix with the blocks, or record and move on)

- N1. Post-remove snapshot defense removed. ensure_visible line 505 reads diag["snapshots"][-1] unguarded. Y4d's version guarded the empty-snapshot case (the _DIAG_JS None bug taught that snapshots can be empty). Current run_live always returns a non-empty snapshot list on VISIBLE, so this cannot fire today, but the hard-learned guard should be restored, not dropped.
- N2. stall_ms is mislabeled. main line 2422 adds the full attempt elapsed_ms for INFRA attempts, but the plan defines stall as seconds spent in hidden-body recovery ladders from ensure_visible timings. No ladder-only timing is accumulated anywhere. Rename the field or measure the ladder.
- N3. Attempt-1 hidden-body encounters are lost from the suite total. Suite hidden_body_encounters (lines 2465-2470) sums only final-attempt summaries plus boot_info. An attempt-1 INFRA runner is discarded, so its encounters survive only in the JSONL. Accumulate encounters across attempts.
- N4. "ONE shared test tab for the whole suite" is fictional. Y4d's log proves the bootstrap tab dies at its session exit (10/10, both runs), and Y9's bootstrap does the same __exit__ (line 2038). Every test will print "shared tab gone, rebootstrap" and pay a fresh-tab bootstrap. The runner handles it correctly, but the plan's "~20 s per-test worst case" understates the real path: per-test rebootstrap plus up to three ensure_visible calls plus the deadline-free rebootstrap in open_fixture's first branch (line 866) can exceed it, and under a Marionette hang each _wd call can take 30 s with no overall suite timeout.
- N5. Handover token is reusable across launches. _check_handover (lines 165-200) checks age under 4 h but binds nothing to this run (no run id or nonce). A token written for an earlier launch passes a second launch inside the window.
- N6. Preflight-failure suite JSON has a different schema from the other failure paths (lines 2280-2290): no bootstrap_intervention, no hidden_body_encounters, no passed or failed counts. A consumer expecting those fields breaks on the preflight path.
- N7. Test-08 td click skips scroll_into_view. run_08 uses d.click_el on the first td (line 1664) while every other click in the runner goes through d.click, which scrolls first (run_live probe v2 vs v4 showed interactability needs the settle). Marionette element click scrolls per spec, so this is a latent false-fail risk, not a proven bug.
- N8. _recheck_shared_tab is self-defeating (see B2): its session exit closes the tab it diagnosed. If the tab had recovered, the recovery is destroyed before the re-run can use it.
- N9. clear_input is dead code. Defined at line 211, never called anywhere in the runner; every clear-then-type step uses type_text, which clears first. Remove it or use it.
- N10. Mid-test diagnose assumes the current window is the test tab. True on all step paths (tests never switch tabs), but unproven on open_fixture failure paths where the last switch may have been a rebootstrap. Those paths already raise INFRA-prefixed errors, so no misclassification results today; if a future path raises non-INFRA from there, the diagnose would read the wrong tab.
- N11. Preflight PID sweep SIGTERM race. Lines 2160-2180 send SIGTERM to a pid whose cmdline is only verified before SIGKILL. If the pid died and was recycled in between, SIGTERM lands on an unrelated process. The window is one sleep(1) wide and the pid was verified alive milliseconds earlier, so this is very narrow, but the cmdline check belongs before SIGTERM too.
- N12. Session-creation failure has no retry, by design. A transient driver-start failure fails the test permanently, while an INFRA failure gets a re-run. The asymmetry is the plan's explicit rule (session failures are not INFRA-blocked), so this is a note, not a demand. If transient starts prove common live, revisit.
- N13. Slot enforcement is manual, not coded. The runner checks Y8's ports free, but the Y8 completion marker (commit regex plus log line) is enforced only by the polling process. If Y8 is live but momentarily between driver sessions (ports free), the runner cannot tell. The launch procedure must check the marker immediately before launching, not only at poll time.
- N14. r.step("check body visible", line 918) logs ok True even when the body is hidden, because Y9Runner.step only fails on exception and ignores a False return. The following r.check is the real gate, but the JSONL line misleads a reader. Either make the step raise on False or drop it.
