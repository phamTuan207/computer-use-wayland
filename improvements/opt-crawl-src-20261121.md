### 3.2 (C-ii) Flicker: what the code can and cannot do

- C5. The capture fence: EVERY observation hides and shows the pill. scripts/cu.py:921 (observe) and line 958 (observe_screen) run grim inside `with capture_clean(STATE)`. indicator.capture_clean() (scripts/indicator.py:257-283) is a re-entrant depth-counted context: at depth 0 it calls request(state, 'hide'), at exit it calls request(state, 'show'), and raises 'indicator session ended during capture' if the show fails. request() (lines 156-193) sends the command over the session socket with a 4s timeout and demands the exact acknowledgement ('hidden\n' / 'visible\n' / 'ok\n'), else raises. So one observe = one hide + one show = two native redraws (see C7). A desktop_act() batch does at minimum: preflight re-observe (hide+show), the action, after-capture (hide+show), plus _settle_after_capture() which can re-capture again (hide+show). That is 4-6 hide/show cycles per batch, in about a second, every time the agent acts. This is the only in-repo mechanism that toggles pill visibility at action time. It cannot produce 10 Hz flicker at idle (no captures happen at idle), but it CAN produce visible blinking on every action batch. Fix must change: scripts/indicator.py capture_clean() and/or scripts/cu.py observe()/observe_screen(), if councils decide captures should not hide the pill (e.g. exclude the pill from the capture region instead of hiding it), or that the hide/show must be debounced.
- C6. The daemon monitor re-sends label + show every 2 seconds, but that does NOT repaint. Daemon._monitor() (scripts/overlay.py:291-305) calls apply_holders() every 2.0s; apply_holders() calls _show_label() (lines 237-254), which sends 'label <text>' then 'show' to the native (or session_label + session_live when owner == 'session'). In the native (native/indicator.c:385-404), a 'show' when already visible only increments duplicate_shows and prints 'visible' WITHOUT redraw; a 'label' with identical text only prints 'ok' WITHOUT redraw. A redraw happens only when the label text CHANGES (and the pill is not hidden). So the 2s monitor tick is visually inert UNLESS the label flips between two holders (two agents acquiring/releasing in turn would alternate the label and redraw on every tick). Fix must change: scripts/overlay.py _show_label()/apply_holders(), to skip the label+show when nothing changed (cache the last label and owner), if councils want the tick to be provably inert.
- C7. The native redraw and quit conditions (native/indicator.c). redraw() (lines 243-256) sets busy=1, queues a draw on every output, arms a 2000ms ack timeout (expired(), lines ~225-241: on timeout it retries ONCE via indicator_should_retry_present(), native/indicator_state.h lines 22-26: retry allowed only when failures < 1, i.e. one retry; a presented frame resets the count to 0; a second consecutive failure sets failed=1 and quits the main loop with 'indicator frame acknowledgement timed out'). input() (lines 363-421): a 'hide' when already hidden is a duplicate no-op; a real hide calls settle_entrance() + redraw('hidden'); a real show calls redraw('visible'); a 'label' with new text redraws when not hidden. THE KILL SWITCH (lines 371-378): if a stdin command arrives while busy (a redraw is in flight), the handler logs 'overlapping', increments overlapping_commands, and QUITS the main loop (g_main_loop_quit). redraw() itself (line 244) does the same if called while busy ('overlapping indicator command', quit). So ANY hide/show/label/move command arriving during a redraw kills the native indicator process. Consequences: (a) the guardian loop then raises 'session indicator lost' (scripts/cursor_session.py:166) and the session dies; (b) the overlay daemon's _ensure_native() (scripts/overlay.py:212-235) respawns ONLY daemon-owned natives, not session-owned ones, so a session pill killed this way stays dead while the session dies with it; (c) the likeliest trigger is a capture_clean hide/show racing a redraw that is still waiting on presentation feedback (slow frame, liquid shader compile, compositor hiccup). This is the strongest in-code candidate for I12 (overlay vanished 15:28 20/11 while the worker lived) and a candidate contributor to flicker: a pill that is repeatedly killed and respawned (daemon) or killed with its session (guardian) reads as flicker/vanish. Fix must change: native/indicator.c input()/redraw(), to queue commands arriving during a redraw instead of quitting (the E1 per-event logging + bounded present retry in commit 40c68f9 already softened the discarded-buffer path; the overlapping-command quit is still a hard quit), and/or scripts/indicator.py capture_clean()/request(), to serialize hide/show against redraw completion.
- C8. The native also quits on: monitor layout change (changed(), lines ~426-430, 'indicator monitor layout changed'); backdrop blur capability lost (capabilities(), lines ~431-438, 'indicator backdrop blur lost'); a registry global disappearing (removed(), lines ~442-448, 'indicator rendering backend lost'); a discarded presentation buffer on the SECOND consecutive failure (discarded(), lines ~173-186, one retry, then 'indicator buffer was not presented'); an output with no drawable width (glass_region(), lines ~190-205); an unreadable output (geometry under 220px wide or under SURFACE_HEIGHT, main() lines ~500-510, 'indicator output too small for a readable status'); missing layer shell / presentation / compositor / effects / BLUR capability / liquid backend at startup (main() lines ~467-495, exit 2 with stderr).
