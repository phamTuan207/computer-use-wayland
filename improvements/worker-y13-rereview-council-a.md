### F2 (BLOCKER): step-count audit counts a harness check as a spec step in JSONL but not in memory, so every passing test fails the audit

- File + line: run_codex_y5.py lines 1165-1166 (open_fixture body check), 1199 (audit_enabled set True only after it), 594-627 (Y13Runner.check/step: log_step always writes JSONL, spec_step_count increments only when audit_enabled), 3084-3105 (_audit_count counts every JSONL record with op in AUDIT_OPS), 3791-3810 (audit block requires jsonl_n == STEP_COUNTS and mem_n == STEP_COUNTS).
- v2 clause violated: plan v2, RT M4, "main() verifies the JSONL step count per test against this frozen table and FAILS the test if short", with the audit counting spec primitives only. The docstring at lines 3060-3064 states the same intent ("Harness ops ... are excluded, so open_fixture ... records never count as spec steps"), but the code does not achieve it: the body check is an r.check, so its JSONL record has op "check", which is in AUDIT_OPS, and _audit_count has no way to tell it apart from a spec check.
- Evidence: simulation importing the real module and the real _audit_count against a synthetic JSONL for a perfectly driven test 01 attempt (86 driver primitives plus the 1 body check) returns 87, while STEP_COUNTS["01"] is 86, so the audit would FAIL. The same +1 applies to every test and every attempt, because open_fixture runs once per attempt. The in-memory counter is correct; the JSONL count is off by exactly one.
- Concrete fix: make auditability explicit on the record. Either (a) tag each log_step record with whether it was written while audit was enabled and have _audit_count count only tagged records, or (b) log the open_fixture body check with a non-audit op (for example "check-harness") and remove "check" from nothing else. Then re-verify by simulation for all 10 tests: jsonl_n must equal mem_n must equal STEP_COUNTS. Do not fix it by raising STEP_COUNTS by 1, that would count a harness check as a spec step and break the in-memory side instead.

### F6 (SHOULD-FIX): guard treats a non-dict verify result as "guard held, proceed" instead of guard-inconclusive

### F7 (SHOULD-FIX): wall cap is enforced only after the attempt returns, not as a deadline during the test

### F9 (SHOULD-FIX, minor): _reload_settings tolerates any click error, not only navigation-related ones

- File + line: run_codex_y5.py _reload_settings lines 2800-2843, called from run_10 lines 2959-2960 (step 21) and 3008-3009 (step 26) via r.step op "click".
