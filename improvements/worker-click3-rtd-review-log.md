### 1.3 Cross-cutting attacks (apply to all three reviews)

C1. Agreement is not independent confirmation. ARCH, GROUNDING, and SPEED all read the same failure record (E2, G30/G31, F2b, clone2 batch 7) and all reach the same direction. That is one evidence base read three times, not three independent measurements. Any claim that appears in all three reviews still rests on the single underlying measurement. The verdict table below discounts accordingly: a proposal is only as strong as its thinnest underlying number.

C2. The "already exists" overclaim pattern. All three reviews say the rewrite is mostly assembly of existing parts (code_exec.py, session_driver.py, dom_act.py, zen_dom.py, cdp.mjs, two_vision_bench.py). These parts were never composed into one running loop. code_exec.py is an in-process program model, session_driver.py is a JSON-lines driver that runs cu.main() in-process per command, dom_act.py grounds through image points, cdp.mjs drives agent-managed Chromium only, and the benchmark is BUILD ONLY and unrun. "Exists" here means "a file exists", not "the composition works". The composition is the work, and it is unproven. Under the 06:07 criterion, the rewrite must prove its win by running, not by listing files.

C3. The deletion-without-replacement pattern. ARCH proposes deleting four components (supervisor tree, overlay server, one-shot SSH, file IPC) whose replacements (driver-owned pill, compositor plugin, broker-only transport, in-process calls) do not exist yet. A deletion whose replacement is a sketch is a regression until the replacement proves. Deletions must be gated on replacements, in that order, every time.

C4. The unmeasured model call dominates everything, and no proposal measures it. GROUNDING P6 names this honestly; the rest of the reviews proceed as if mechanism time were the whole game. If a task needs 2-3 model calls at 10-30s each, the floor is 30-60s regardless of transport, and the 10s target is unreachable by any mechanism change. Every speed projection below is therefore conditional on an unmeasured number. This does not kill the proposals; it caps what they can promise.

C5. The single-runner lock and the one-session constraint are load-bearing and mostly unexamined. ARCH keeps the lock (G-SINGLE-LIVE) but moves it into the driver without a design. GROUNDING notes Firefox allows exactly one remote session per instance (proven in 4 runs) but P7 does not resolve whether grounding and input can share one protocol. Any daemon or runner that holds a session for a whole task blocks every other tool for that whole task. This is a lock-in risk no review prices in.
