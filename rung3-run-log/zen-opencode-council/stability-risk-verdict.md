## Global conditions on every APPLY

- **One controlled restart, total.** Every pref change needs a Zen restart to take effect (prefs.js is read at startup). Bundle all approved prefs into a single pre-run restart tonight, then re-verify: ports 9222/2828 live, tab set intact, `about:config` shows the new values. Never restart per pref.
- **No deliberate crash test on the live profile tonight.** P0-1/P0-2 full verification as written needs `kill -9` twice in a row. That is a destructive test on the frozen profile the night before the run; Mozilla documents the semantics, and a config read plus one clean restart is sufficient evidence. If the coordinator wants proof of crash behaviour, do it on a throwaway profile, not the run profile.
- **P0-1 removes the browser's own circuit breaker**, so it is APPLY only with an external one: the watchdog must cap consecutive restarts and alert instead of looping forever.

| P0-1 `toolkit.startup.max_resumed_crashes` -1 | **APPLY** | Removes the safe-mode dead end. Issue #16694 (open, confirmed) means 3 crashes + safe mode = a hung profile lock a watchdog cannot fix. -1 is Mozilla's own automation value, present in the RP set I verified. Risk (infinite crash loop) is real but is transferred to the watchdog, which must cap restarts; that is the correct place for the cap. | Shipped default 3, verified in installed `firefox.js`. | P0-2 `browser.sessionstore.max_resumed_crashes` 10 | **APPLY** | At the shipped default of 1, the second consecutive crash silently loses the tab set, which is worse than a visible failure. 10 is bounded, not infinite. `resume_from_crash` stays true (verified default true). | Shipped default 1, verified. Not in Mozilla's RP set (verified absent), so this is the report's own value, but the direction is right and the bound is sane. ## Rejected list: agree with every rejection

| Rejected candidate | Agree / disagree | Reason |

| `fission.autostart = false`, `browser.tabs.remote.autostart = false`, `dom.ipc.processCount = 1` | **Agree** | Collapsing to one content process removes the isolation that contains crashes: one tab hang becomes a whole-run hang. The opposite of stability. |

## One additive item the report mentions but does not put in the apply list

One line, no behavioural risk beyond blocking updates, which is already the intent. Bundle it into the single pre-run restart.
