RULE: A task is Class L (exception) ONLY if the scorer must verify state that is
BOTH created/modified by the runner AND destroyed by the reset AND not preserved
in the sealed snapshot. If verification can be done from the sealed snapshot files
alone (screenshot, ket-qua.txt, saved CSV/PNG/MP3/GIF, online doc that persists),
it is Class S (snapshot-sufficient, decoupled scoring is OK).

CLASS L (exception, score-before-reset, runner waits): 5 tasks
- R3-001: scorer re-opens TodoMVC live and compares. Todos live in browser storage;
  reset wipes them. Screenshot alone is not what the key asks the scorer to verify.
- R3-055: scorer opens each directory and checks permissions. Live filesystem tree;
  reset wipes it. A screenshot cannot substitute for a live permission check.
- R3-074: scorer re-runs a read-only script and compares 10 lines. The script reads
  live files the reset restores, so a post-reset re-run gives fixture output.
- R3-075: scorer checks the venv exists and packages are installed. Live filesystem;
  reset wipes the runner's venv.
- R3-089: scorer re-runs find (read-only) on the live log files in ~/rung3/nd09-logs.
  Reset restores those files to fixture state, so a post-reset re-run is wrong.

COUNT: 5 of 55 run tasks are Class L (9 percent). This is the minority the council
expected (Members 1 and 2), not Member 3's conservative 33. The decoupling saving
is therefore on the larger side. If the exception list cannot be produced, the
serial pipeline stands (fail-safe). This list IS produced, so decoupling applies
to the 50 Class S tasks.

FAIL-SAFE: if a task is found at run time to need a live re-read that this list
missed, the coordinator moves it to score-before-reset for that task and records
the correction here. No task is decoupled on a guess.
