# FCC-K realistic test cases

10 hard realistic computer-use tests for Pham Tuan, generated by Worker K
(fcc-claude). Each lives in its own file `tests/realistic/fcc-k/test-XX-name.md`
with a matching offline fixture HTML under `tests/realistic/fcc-k/fixtures/`.

## Topics (do not overlap the clone topics)
01 spreadsheet data entry + formula check
02 email triage + reply drafting
03 calendar scheduling across conflicts
04 research + note taking across 3 sources
05 image download + organize + rename batch
06 settings configuration across 2 apps
07 bug reproduction: reproduce a UI bug and document it
08 form with validation errors: submit, read errors, fix, resubmit
09 copy data between app A and app B with format conversion
10 long document edit: find/replace, add table, export

## Contents of each test file
- Test ID, Topic, Context, Goal
- Exact steps (15-40 steps each)
- Pass/fail criteria
- What to time (per-step wall time + total wall time)
- Errors designed to expose (click miss, slow think, stale observation,
  wrong diagnosis, fabrication)
- Checker script or exact expected end state

## Running the automated checker offline
Each fixture is a self-contained local HTML app exposing
`window.__fcckVerify()` which returns a JSON verdict `{passed, failures,
score, state}`.

Run one test offline (no network, no external sites):

```sh
node tests/realistic/fcc-k/check.mjs \
  --fixture tests/realistic/fcc-k/fixtures/test-01-spreadsheet.html \
  --test 01
```

The checker launches headless chromium via puppeteer-core (default executable
`/usr/bin/chromium`; override with `CU_CHROME_PATH`), opens the fixture via
`file://`, calls `__fcckVerify()`, prints JSON, and exits 0 on pass.

All 10 checkers were verified offline during generation (each returned
passed:true).
